# Architectural decision records

Record decisions that explain lasting constraints or costly-to-reverse choices.
Routine implementation details and transient PR findings do not need an ADR.

Use numbered descriptive files such as `0002-example-decision.md`. Each record
should state its status (proposed, accepted, superseded, or descriptive baseline),
date, context, decision, consequences, alternatives, and links to supporting evidence.
Do not label a proposal accepted without an actual decision. Preserve superseded
records and link their successors.
